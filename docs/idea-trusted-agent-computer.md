| الحكم | التفصيل |

**الخلاصة في سطر:** لا نبني «Manus أقوى» — نبني **الحاسوب الذي يُوظِّف الوكلاء تحت سيطرة بشرية موثّقة**، في مجال الحملة الانتخابية وبياناتها الحسّاسة. هناك تكون «الثقة» هي المنتج، والاستقلالية بلا مساءلة = مسؤولية.

## 1. ما هو «كمبيوتر Manus» فعلًا؟ (تحليل لا تسويق)

Manus = وكيل عام يعمل داخل **حاسوب افتراضي معزول لكل جلسة** (متصفح + طرفية + نظام ملفات) يخطّط ويُنفّذ مهامًا طويلة بأقل تدخل، بمعمارية **منظّم + وكلاء متخصصون** (تصفح/كود/بيانات/ملفات) فوق نماذج Claude-class [1][2].

| نقطة قوته | نقطته الضعيفة — **وهنا يتفوق المشروع** |
| --- | --- |
| استقلالية طويلة الأمد بلا إشراف | **لا شهادات أمنية منشورة** (SOC 2/ISO) — حتى مراجعاتهم تحذر من إدخال بيانات حسّاسة [1] |
| متصفح وطرفية وملفات حقيقية | **شفافية غير مكتملة**: الجلسة تُدمَّر بعد المهمة، والـcollaboration تكشف الصندوق كاملًا للشركاء [2] |
| جلسات قابلة للإعادة (replay) | **صلاحيات بلا طبقات**: الوكيل بداخل الـsandbox بجذر النظام؛ الثغرة تبقى محصورة لكن البيانات لا [2] |
| امتداد Browser Operator بجلساتك الحقيقية | **أكبر مخاطرة أمنية معروفة**: التحكم بحساباتك ونظامك المحمي — خيار لا تقبله حملة انتخابية أبدًا [3] |
| توليد مخرجات كاملة (تقارير/مواقع/عروض) | **تكلفة بالرصيد** وصندوق مغلق بلا SDK مخصص [3] — والاعتماد على مزوّد واحد |

## 2. أين نتفوق — جدول المعركة الحقيقي

| البعد | Manus | Leader 2027 (المسار المقترح) |
| --- | --- | --- |
| الهدف | مهمة عامة مفتوحة | **عمليات حملة انتخابية** — عمود فقري وظيفي حقيقي (أشخاص/متطوعون/ميدان/مؤشرات) |
| اللغة والميدان | عام | **عربي أولاً** + واقع الميدان المصري (تقرير من الشارع لا من المكتب) |
| الضمانات | sandbox + أمل | **موافقة بشرية single-use + تدقيق + صلاحيات على الخادم** — قائمة منذ VS4 |
| الخطوط الحمراء | قابلة للتجاوز بالـprompt | **§5 مفروضة على مستوى validation والمخطط** — مخرجات الوكلاء تُرفض صراحةً |
| البيانات | تخرج إلى سحابة الطرف الثالث | **سيادة البيانات**: نماذج محلية اختيارية (Ollama) — «صفر اعتماديات خارجية» يبقى مبدأً لا شعارًا |
| المساءلة | سجلات داخلية | **سلسلة «مَن فوّض مَن» كاملة** (`on_behalf_of` + سلطة المُعتمِد لا أعلى) |
| التكلفة | رصيد مدفوع/مجاني محدود | تشغيل مجاني يتسق مع خطة النشر بلا بطاقة (`docs/deploy-free-roadmap.md`) |

## 3. الأفكار الحديثة (2026–2027) — مرتبة بعائد ÷ مخاطرة

| # | الفكرة | لماذا هي حديثة؟ | العائد ÷ المخاطرة |
| --- | --- | --- | --- |
| **1** | **سطح MCP للكتالوج والموافقات** | MCP = «TCP/IP للوكلاء» — تبنّته OpenAI/Google/Microsoft [5] | ⭐⭐⭐⭐⭐ — بنية صغيرة فوق `GET /api/kernel/cells` و`POST /api/kernel/actions` **القائمتين** |
| **2** | **منظّم + وكلاء متخصصون (org-chart لا وكيل واحد)** | اتجاه 2026 الحاسم: فرق وكلاء مُتخصصَّة ينسّقها منظّم — نفس معمارية Manus لكن فوق ناقلنا المعزول | ⭐⭐⭐⭐ |
| **3** | **ذكاء اصطناعي «مُحاكِم» قبل البوابة** | وكيلان متنافسان (مُحلِّل/مُنتقد) + حكم بشري — يرفع جودة الطلب قبل الاعتماد | ⭐⭐⭐⭐ — بلا مخاطرة: القراءة لا تحتاج موافقة |
| **4** | **ذاكرة دائمة + RAG بفلتر §5 ثنائي** | الذاكرة الدائمة صارت معيارًا (دقّة أعلى + تكلفة أقل) [4] — وفلتر §5 عند القراءة **والكتابة** يمنع حتى حقن التعليمات (prompt injection) | ⭐⭐⭐⭐ — يعتمد على T1 (Postgres) |
| **5** | **سِجل جلسة قابل للإعادة (Agent Replay)** | امتداد طبيعي للتدقيق الموجود: شريط زمني لما «رأى وفكّر ونفّذ» الوكيل — شفافية Manus لكن مع سلسلة مساءلة | ⭐⭐⭐ |
| **6** | **نماذج محلية/سيادية (Ollama / llama-class)** | السيادة والخصوصية من أبرز اتجاهات 2026 [4] — ويحفظ مبدأ «بلا اعتماديات خارجية» | ⭐⭐⭐ — جودة أقل من النماذج الكبرى، تكفي للتلخيص/التصنيف |
| **7** | **«هاتف الميداني هو الحاسوب»** | Computer-use/GUI agents اتجاه 2026 [5] — والتطبيق الحقيقي لحملتنا: تقرير صوتي عربي → تقرير منظَّم + مزامنة دون اتصال | ⭐⭐⭐ — شريحة كبيرة لاحقة |
| **8** | **مُحاكاة وتوقّع (قراءة فقط)** | توأم رقمي «ماذا لو غطّينا المنطقة كذا؟» — بلا كتابة إذًا بلا موافقة | ⭐⭐ |

### فكرة مركّزة تستحق الاسم: **«بوابة الوكلاء» (Agent Gateway)**
بدل بناء حاسوب منافس: **نافذة واحدة يمرّ منها كل وكيل** — خارجي أو محلي — تعرض:
1. الكتالوج (`ai.catalogue` — 27 أداة مُعلَنة) عبر **MCP**.
2. طلبات الكتابة → `pending_approval` → إنسان (`users:manage`) → تصريح **مرة واحدة**.
3. كل شيء في AuditEvent مع `on_behalf_of: agent:<name>`.
**Manus نفسه يصبح «موظفًا مُشرَفًا» لا منافسًا** — وهذه أقوى استجابة ممكنة لسؤال «كيف نتفوق على كمبيوتر Manus؟».

```text

        ↓
V5.1 سطح MCP (قراءة) → V5.2 طلبات الموافقة عبر MCP → V5.3 منظّم + وكيلان → V5.4 ذاكرة+RAG → V5.5 Replay
```

- **الانضباط لا يتغيّر:** كل شريحة عقد + إثبات + بوابات؛ «لا ادعاء بلا إثبات» يشمل أي ادعاء «تفوّق».

## 6. خطوط حمراء لا تُساوَم

- **§5 ممتد إلى الوكلاء:** لا انتماء سياسي ولا «درجة إقناع» ولا استنتاجها — يُرفض في validation لا في الـprompt.
- **لا كتابة بلا إنسان:** بوابة الموافقة الحالية باقية — وكل ميزة جديدة تمرّ منها.
- **لا سيطرة متصفح بحسابات المستخدمين** (ثغرة Manus الأشهر [3]) — ممنوع مبدئيًا في هذا المشروع.
- **لا اعتماديات خارجية إلزامية:** النماذج المحلية الخيار الافتراضي؛ أي مزوّد سحابي اختياري وموثّق.
- **لا وعود «يتفوق على منافس» في الوثائق الرسمية** — نُثبِت بالقياس والاختبار لا بالمقارنة التسويقية.

## 7. In English (short)

- **Opinion:** don't fight Manus on raw autonomy (Meta-backed sandbox VMs, multi-agent planners, full browsers) — fight on **verifiable trust**. In 2026–27, human-in-the-loop governance has become a strategic architecture, not a limitation [4][5] — and Leader 2027 already ships what enterprises are scrambling to build: single-use human approvals, full audit chain, server-side permission matrix, §5 hard validation, cell isolation.
- **Killer idea:** an **Agent Gateway (MCP surface + approval queue)** that turns Manus and any external agent into a *supervised employee* of the campaign: it can see the 27-tool catalogue, request writes, and never write without a human's single-use authorization.
- **Modern ideas ranked:** MCP surface → orchestrator + specialist agents → adversarial pre-gate review → persistent memory + dual-filtered RAG (§5 at read & write) → agent session replay → local/sovereign models (Ollama) → offline-first Arabic field voice → read-only simulation.
- **Sequencing:** T1 (Postgres deploy gap) lands first; then a locked `docs/contract-vs5.md`; slices V5.1→V5.5, each with tests and smoke evidence.
